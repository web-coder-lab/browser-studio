Safety

Do not paste GitHub or Render tokens into this app or into chat. This project does not use GitHub as a user database.

How Browser Studio works now

  1. Create account: enter Gmail → 6-digit code → display name, username, password.
  2. Log in with that email and password. The account is confirmed only after login.
  3. Forgot password uses the same email-code path.
  4. Your project files save to Firebase, not the Render disk.
  5. Use the file icon for files, search icon for find, tree icon for outline. Run starts preview.
  6. HTML/CSS/JS preview is real in the browser. There is no remote Linux server and no fake custom-domain attach.

1. Create an account

Open the app → Register. Need: display name, username (3+), email, password (6+).

There are no built-in demo users. Old sample accounts were removed so hashes and fake API keys are not exposed.

Then use Sign In with the same username/email and password.

2. After login

  • Left rail: files, search, git-style panel (local UI).
  • Center: code tabs. Edit HTML, CSS, JS for preview.
  • Bottom: terminal / tools dock.
  • Status bar: file and cursor info.

3. Preview

Open index.html, related CSS/JS, then use the preview pane. Preview runs in a sandboxed iframe on your machine.

4. Local server (real save)

Run node server.js. This API is real:

  • GET /api/health
  • POST /api/register
  • POST /api/login
  • GET /api/me (Bearer token)
  • GET/POST /api/workspace — files stored under data/ on this computer

Unknown API paths return JSON 404. Unknown pages can show 404.html.

5. Settings

Theme, font size, wrap, and related editor toggles stay in the Settings modal. They do not grant extra cloud power.

6. What is not real (removed or locked)

  • One-click GitHub push / Render deploy from chat tokens
  • Custom domain attaching your project to the public internet
  • Fake “SSL valid” badge
  • Host Linux shell, nmap, cloudflared tunnels
  • APK / Electron / PWA exporters
  • AI coder
  • On-screen dump of all users and password hashes

7. Domain tool

A DNS lookup can only tell you if a name has public A/CNAME records. It does not point that domain at your IDE unless you configure DNS at your registrar and host the built site yourself.

8. Team panel

Names you add are local to the browser unless you build real invites later. Do not treat it as a live multiplayer server.

9. Keyboard (browser)

  • Normal typing in the editor
  • Use the app search modal if it is open in the toolbar
  • Logout from the account / auth control

10. Run locally

cd browser-studio

node server.js → API + help + 404

Frontend UI (if you install Node packages on your PC): npm install then npm run dev

11. Host it yourself

On your own Render/Vercel account: build the frontend, start node server.js, set PORT. Never commit tokens. Never put user passwords in a GitHub repo.

12. Kids / school use

This is a learning IDE. Keep content school-safe. Do not store other people’s passwords.
