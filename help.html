Browser Studio — full help

How every real screen works. What was removed because it was fake.

Open the studio
Do not paste secrets here

Never put GitHub, Render, Gmail app passwords, or Firebase keys in the editor or in chat. Keys live only in the host dashboard.

1. Create an account (required path)

  1. Open the app. Choose Create account.
  2. Enter your Gmail / email and send the code.
  3. Read the 6-digit code from email (or the on-screen dev code if mail is not configured yet).
  4. Enter display name, username, and a password of 8+ characters.
  5. The account is stored. You are still logged out.
  6. Choose Log in with the same email and password. Only then the studio opens.

2. Log in and stay signed in

Login asks the server for a session token. Refresh keeps you signed in until you log out. Logout clears the token.

3. Forgot password

  1. Choose Forgot password.
  2. Send a recovery code to the same email.
  3. Enter the code and a new 8+ character password.
  4. Log in with the new password.

4. After login — one icon per place

  • Files icon — project files
  • Tree icon — outline of the open file
  • Search icon — find in files
  • Run — preview HTML/CSS/JS in the right pane
  • Code / Split / Design — only those three view modes
  • Account — who you are
  • Settings — editor size, help, honest limits

There is no extra team button, deploy wizard, or domain attach button.

5. Files and save

While you are signed in, the editor saves the file tree to Firebase through POST /api/workspace. Reloading loads GET /api/workspace. Nothing is stored as a database on the Render disk.

6. Preview and Run

HTML, CSS, and JavaScript run in a sandboxed preview in your browser. That part is real. Python / SQL helpers that exist in the UI also run in the browser, not on a hidden Linux VPS.

7. Real API routes

  • GET /api/health
  • POST /api/auth/otp
  • POST /api/auth/otp/verify
  • POST /api/auth/register
  • POST /api/auth/login
  • POST /api/auth/recovery
  • GET /api/auth/me
  • POST /api/auth/logout
  • GET /api/workspace and POST /api/workspace

Unknown /api/... paths return JSON 404. Unknown pages serve the studio or /404.html.

8. What was removed because it was not real

  • Demo users and exposed passwords
  • One-click GitHub + Render deploy from the editor
  • Custom domain attach and fake SSL badges
  • Remote Linux / nmap / tunnel toys
  • Live team invites
  • Hard-coded live API keys

9. Owner setup (once)

  1. Firebase Console → project early-networks → create Firestore (Native mode).
  2. Optional: create Storage if you will store APK/json files later.
  3. Render env already has Firebase project, client email, and private key.
  4. Add Gmail app password later so OTP goes to real inboxes. Until then, a dev code is only shown when the server is not in production mail mode.

10. School-safe use

This is a learning editor. Keep projects school-safe. Do not store other people’s passwords.
